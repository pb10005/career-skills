# キャリア戦略の策定

## このスキルが解こうとしている問題

キャリアの相談は、放っておくと次の3つの失敗形に落ちる。

1. **「転職するかどうか」の二択に潰れる。** 実際には、現職で異動する・役割を変える・時期をずらす・条件を交渉する、といった選択肢が常にある。二択に縮めると、比較していないだけの決定になる。
2. **不満の裏返しで意思決定してしまう。**「今がつらいから変える」は方向を決めない。何から逃げるかではなく、何に向かうかを言語化しないと、次も同じ理由で行き詰まる。
3. **一般論で終わる。**「市場価値を高めましょう」「まずは棚卸しを」で終わる助言は、読んだ瞬間は納得できるが、翌日の行動が何も変わらない。

このスキルの仕事は、**選択肢を実際に並べ、比較軸を明示し、期限と最初の一歩まで落とした1枚の文書を作ること**にある。

## 成果物

5部構成の戦略メモを1本作る。長くても A4 2枚に収める。読み返して決断するための文書であって、網羅的な分析レポートではない。

```markdown
# キャリア戦略メモ（YYYY年MM月）

## 1. 現状
   事実 / 満足していること / 不満 / 制約
## 2. 選択肢
   3〜5案。必ず「現職に留まる」案を含める。各案に前提・想定・リスクを書く
## 3. 推奨
   どれを、なぜ、いつまでに。選ばなかった案を捨てた理由も書く
## 4. アクション
   期限付き。最初の1つは1週間以内に着手できる大きさにする
## 5. 前提と再検討の条件
   この判断が依存している仮定と、それが崩れたら見直すという線
```

最後の「前提と再検討の条件」を必ず入れる。キャリアの判断は不確実な情報の上に立つので、**何が変われば結論が変わるのかを書いておかないと、状況が動いたときに惰性で古い結論を実行してしまう。**

## 最初にやること

**相談文に次のどれかがあれば、ヒアリングを始める前に `references/frameworks.md` を読む。** 判断の骨格になる材料がそちらにあり、読まずに進めると見落とす。

- 疲弊・消耗のサイン（「しんどい」「疲れた」「何をしたいか分からない」「気力がない」）
- 家庭・ライフイベント（出産、育児、介護、住宅購入、配偶者の転勤）
- 上司や特定の人物への言及
- 具体的な求人やオファーの比較

どれも無ければ Stage 1 から始め、詰まったところで読む。

## 進め方

```
Stage 1  事実の確認      経歴・現在の条件・制約
Stage 2  不満の分解      何が嫌なのか。誰の問題か。転職で解けるのか
Stage 3  志向の言語化    何に時間を使いたいか。何を犠牲にできるか
Stage 4  市場の照合      何が売れるのか。情報の出どころを明示する
Stage 5  選択肢の列挙    3〜5案。ここで初めて選択肢を出す
Stage 6  比較と推奨      軸を決めて比較し、推奨を1つ出す
Stage 7  アクション化    期限と最初の一歩
```

1ラウンドの質問は4問まで。選択式で答えられるものは選択式にし、選択肢には「それを選ぶと検討がどう変わるか」を添える。

**聞きたいことが4問を超えたときの優先順位。** 各ステージの「必ず聞く」を全部足すと1ラウンドに収まらない。次の順で先に聞き、残りは次ラウンドに送る。

1. **健康・疲弊の状態** — これが赤なら他の議論の前提が崩れる。最優先で確認する
2. **時期の制約**（出産・介護・住宅ローン・プロジェクトの区切りなど） — 選択肢の集合そのものを変える。後から出てくると検討をやり直すことになる
3. **不満の切り分け**（会社か、上司か、職種か、働き方か） — 打ち手の方向を決める
4. **満足している要素** — 比較軸に必要だが、次ラウンドでも間に合う
5. **志向の言語化**（Stage 3） — 重み付けの材料。急がない

送った質問は「次のラウンドで聞くこと」として明示する。聞き漏らしたのではなく順序の判断だと伝わるようにする。

**まとまった返信が一度しか返ってこない状況では、ステージを圧縮する。** メール的なやり取りや単発の相談では7ラウンド回せない。その場合は (1) 上の優先順位で4問を選び、(2) 残りの質問を「これも教えてください」として列挙し、(3) 現時点で言える構造的な観察（選択肢の候補、確認すべき制度、情報の確度）だけ先に返す。**推奨は材料が揃うまで出さない**という原則は、圧縮しても変えない。

**Stage 5 より前に選択肢を出さない。** 早い段階で「転職しましょう」「留まりましょう」と方向を示すと、以降のヒアリングがその結論を裏付ける材料集めになってしまう。

## Stage 2: 不満の分解（最重要）

「今の仕事が不満」は、そのままでは方向を決めない。**不満を分解して、転職で解けるものとそうでないものを分ける。**

聞く順序:

1. 「一番変えたいことを1つだけ挙げるとしたら何ですか」
2. 「それは**会社**の問題ですか、**部署・上司**の問題ですか、**職種**の問題ですか、**働き方**の問題ですか」
3. 「その問題は、**今の会社の中で**解ける可能性はありますか。異動・担当変更・交渉で変わりませんか」
4. 「もしそれが解決したとして、あと2年この会社にいますか」

3 と 4 が効く。多くの場合、不満の実体は**部署や上司**にあり、それは社内異動でも解ける。逆に 4 に「いいえ」と答えるなら、問題は不満そのものではなく**この先の展望**にある。この2つは打ち手がまったく違う。

同時に、**満足している要素も必ず聞く。** 転職すると失うものであり、比較軸として不可欠なのに、不満を語っているときには本人の視界から消えている。

### 疲弊のサインを必ず拾う

「しんどい」「疲れた」「気力がない」「何をしたいか分からない」が出たら、不満の分解に入る前に状態を確認する。**ここを素通りして不満分解を進めるのが、このスキルで最も起きやすい失敗。**

> 「『しんどい』の中身は、次のどれに近いですか。(a) 忙しくて時間がない (b) 忙しくはないが無力感・張り合いのなさ (c) 眠れない・休日に回復しない・体調に出ている (d) 何をしたいか考える気力がない」

**(c) と (d) が出たら、キャリアの相談として処理しない。** 有給・休職・受診で状態を戻してから決める、という選択肢を必ず提示する。相談自体は止めなくてよいが、重い判断は延期する前提に切り替える。詳しくは `references/frameworks.md` の「不満の切り分け表」の最終行を読む。

### 上司が「変わった」ケース

「上司が変わってから」という語り方は、特定の人物への不満とは別の型である。**前任者の下では成立していたという比較対象が既にあり、かつ上司の側が先に異動する可能性がある。** 待つことが現実的な選択肢になりうるので、それを見積もる材料を聞く。

> 「今の上司はいつ着任しましたか」「その組織では、管理職はどのくらいの周期で異動しますか」「前の上司のときは何が違いましたか」

異動周期が2〜3年の組織なら、「待つ」が選択肢として成立する。転職の準備と並行して待てるなら、可逆性の高い案になる。

## Stage 3: 志向の言語化

「何がやりたいか」を直接聞くと答えられないことが多い。**具体的な選好を聞いて、そこから逆算する。**

- 「直近1年で、時間を忘れて取り組めた仕事は何でしたか。何がよかったのですか」
- 「逆に、一番やりたくなかった仕事は。何が嫌だったのですか」
- 「5年後、**周りからどういう人だと思われていたい**ですか」
- 「年収・裁量・安定・時間・成長のうち、**今いちばん削れないもの**はどれですか。**逆に、今なら削れるもの**は」

最後の「削れるもの」が重要で、**トレードオフを認めた瞬間に選択肢が具体化する。** すべてを取りにいく前提のままでは選択肢が比較できない。

## Stage 4: 市場の照合 — ここでの誠実さ

**年収相場・求人動向・企業の内情について、確かめていないことを断定しない。** キャリアの判断は生活に直結するので、もっともらしい数字を出す害が大きい。

- Web 検索が使えるなら**検索して、出典を明示する**。転職サイトの相場情報、公開されている賃金統計、企業の採用ページなど
- 使えないなら、**「これは推定です」と明示するか、本人に調べてもらう項目としてアクションに入れる**
- エージェントとの面談、カジュアル面談、求人票を見る、といった**情報収集そのものをアクションとして設計する**のが実務的に最も有効

書いてよいのは、本人の経歴から言える構造的な話である。「この経験の組み合わせは母数が少ない」「この職種は経験年数より実績で見られる傾向がある」といった観察は、根拠を添えれば有用。数字を装った推測は有害。

## Stage 5: 選択肢の列挙

**3〜5案。必ず次を含める。**

- **現職に留まる（何も変えない）** — 比較の基準線として必要。これを置かないと他の案の良し悪しが測れない
- **現職の中で変える** — 異動、担当変更、役割の追加、条件交渉。転職より低コストで、見落とされやすい
- **転職する** — 方向が複数あるなら分けて書く（同職種で条件改善／職種を変える／業界を変える など）

必要に応じて、独立・フリーランス、進学・留学、副業からの助走、時期をずらす（1年後に動く）も入れる。

各案に**前提・想定される結果・リスク・可逆性**を書く。特に**可逆性**は軽視されやすい。戻れる選択と戻れない選択では、同じ期待値でも取るべき態度が変わる。

## Stage 6: 比較と推奨

比較軸は本人の Stage 3 の回答から作る。**汎用の軸を押し付けない。** よく使われるのは次だが、本人が「今は年収より裁量」と言ったならその重みで並べる。

年収 / 裁量・意思決定の範囲 / 学べること / 安定性 / 時間・場所の自由 / 可逆性 / 実現までの時間

推奨は**1つに絞る。** 「A も B もあり得ます」で終わるのは、判断を返しているだけで仕事をしていない。ただし**選ばなかった案を捨てた理由を書く**。後で状況が変われば、その理由が変わったかを見れば再検討できる。

推奨が本人の希望と違う場合は、そう言う。理由を添えて一度伝え、それでも本人が選ぶならその方針でメモを完成させる。決めるのは本人である。

**「今は決めない」も正当な推奨である。** 疲弊が主因の場合、あるいは判断に必要な情報が決定的に欠けている場合、推奨欄に書くべきは「回復・情報収集を優先し、〇月に再検討する」になる。これは判断の放棄ではなく、**期限を切った延期という判断**であり、選択肢を比較した結果として書く。

その場合、選択肢の欄には転職先の候補ではなく、**延期の期間中に取れる手**を並べる（有給・休職の取得、異動の申請、受診、情報収集のみ行う、現状維持）。アクションは回復と情報収集に限定し、応募や退職交渉を入れない。再検討の時期は「5. 前提と再検討の条件」に明記する。

## Stage 7: アクション化

期限のない行動計画は実行されない。**各アクションに期日と、完了が判定できる形を与える。**

- 悪い例:「市場価値を把握する」
- 良い例:「今週中に転職サイトに登録し、来週末までにエージェント2社と面談を入れる」

**最初の1つは1週間以内に着手できる大きさにする。** キャリアの意思決定は先延ばしされやすく、最初の一歩が重いとメモごと放置される。

情報が足りなくて決められない項目は、**「決める」ではなく「調べる」をアクションにする**（例:「現職の異動制度の申請時期を人事に確認する」）。決断を保留すること自体を計画に組み込むほうが、曖昧なまま先送りするより健全。

## CV 作成との連携

戦略が決まったら、応募書類はその戦略に従って書き分ける。`cv-writer` スキルがあればそれを使う。連携のポイントは次の2つ。

- **戦略メモの「推奨」が、職務経歴書の職務要約と自己PRの方向を決める。** リードに行きたいなら体制規模と意思決定の実績を前に出し、専門性を深めたいなら技術判断の深さを前に出す。同じ経歴でも重点が変わる。
- **応募先のタイプが複数あるなら、書類も分ける。** 汎用版1本で全方向に出すと、どの応募先にも刺さらない。

逆に、経歴の棚卸しをしている途中で「そもそもどこに出すべきか」が問題だと分かったら、CV 作成を止めてこのスキルに戻る。

## やってはいけないこと

- **年収相場や企業の内情を、確かめずに断定しない。** 生活の判断材料になるため害が大きい。推定なら推定と書く。
- **転職ありきにしない。** 現職に留まる案を必ず選択肢に入れる。相談してきた時点で本人は動く方向に傾いていることが多く、その傾きをそのまま増幅するのは助言ではない。
- **本人が言っていない不満を推測で書かない。** 「本当はこう思っているのでは」という解釈は、確認してから書く。
- **一般論で締めない。** メモを読んだ翌日に何をするかが書かれていなければ、まだ終わっていない。
- **健康・家庭・法務に関わる要素が出てきたら、その扱いを明示する。** メンタルの不調、ハラスメント、契約上の制約（競業避止など）が絡む場合、キャリア戦略の枠内で処理せず、専門家に相談する項目としてアクションに分ける。

判断の材料になる観察や質問は `references/frameworks.md` にまとめてある。冒頭の「最初にやること」に該当すれば先に読む。該当しなくても、ヒアリングが止まったとき、比較軸を作るとき、選択肢が2つしか出てこないときに読む。
